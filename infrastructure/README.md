# Yaadon AWS infrastructure

This AWS CDK application defines the private upload-storage foundation. The CDK source remains in this repository; it is not manually uploaded to the AWS Console. During deployment, CDK synthesizes CloudFormation and submits it to AWS using temporary IAM Identity Center credentials.

## What the development stack creates

- One private S3 bucket for short-lived raw uploads.
- One private S3 bucket for sanitized photographs.
- S3 bucket policies that reject non-HTTPS access.
- S3-managed encryption, ACLs disabled, and every public-access mechanism blocked.
- Sanitized uploads expire after one day and generated outputs after seven days;
  server-controlled master templates under `templates/` are retained.
- CORS restricted to `http://localhost:3000` for development.
- One on-demand DynamoDB table for upload ownership, expiry, idempotent results, and rate limits.
- DynamoDB TTL and one-day S3 lifecycle backstops.
- An hourly Lambda triggered by EventBridge to enforce configured upload retention.
- One-week CloudWatch retention for cleanup logs without photo bytes or object keys.

Resource names are generated by CloudFormation to avoid collisions. Both buckets and the DynamoDB table are retained if the stack is deleted, so an accidental `cdk destroy` cannot erase customer state.

## 1. Configure AWS CLI access

Install AWS CLI v2, then configure the IAM Identity Center profile:

```powershell
aws configure sso --profile arun-admin
aws sso login --profile arun-admin
aws sts get-caller-identity --profile arun-admin
```

The final command should show the intended AWS account. Do not proceed if it shows a different account.

## 2. Install and inspect locally

From the project root:

```powershell
pnpm install
pnpm infra:synth
```

`infra:synth` is local and creates no AWS resources.

## 3. Bootstrap CDK once

Replace `YOUR_12_DIGIT_ACCOUNT_ID` with the account shown by the identity check:

```powershell
.\node_modules\.bin\cdk.cmd bootstrap aws://YOUR_12_DIGIT_ACCOUNT_ID/ap-south-1 --profile arun-admin
```

Bootstrapping creates the standard CDK deployment resources in the Mumbai region. It is required once per account and region.

## 4. Review and deploy development storage

Set the temporary profile for the current PowerShell window:

```powershell
$env:AWS_PROFILE = "arun-admin"
pnpm infra:diff
pnpm infra:deploy:dev
```

Review the `diff` before deploying. CDK asks for approval if a deployment broadens IAM or security permissions. After deployment, CloudFormation outputs the generated raw bucket, sanitized bucket, and upload-state table names.

For local AWS testing, copy `.env.example` to `.env.local`, set `UPLOAD_STORAGE_PROVIDER=aws` and `RATE_LIMIT_PROVIDER=dynamodb`, then copy the three CloudFormation output names into the corresponding AWS variables. Keep `AWS_PROFILE=arun-admin` in the PowerShell process that starts Next.js; never copy SSO cache contents or access keys into the environment file.

## Production

Do not deploy a production stack into the current account yet. Create or select the production workload account, use its IAM Identity Center profile, bootstrap that account/region, and provide the deployed HTTPS application origin. Production commands will be added when that account boundary and hosting origin are approved.
